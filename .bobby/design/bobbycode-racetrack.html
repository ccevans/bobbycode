Three commands,
in the order that matters.

Plan before you build. Build before you ship. bobby holds the order, because a bad plan is what you pay for three corners later.

1 SECTOR 1PLAN

Walk the track first.

Describe what you want the way you'd say it out loud. bobby drafts a plan with acceptance criteria and test cases. You edit it, argue with it, approve it. Nothing gets written until you do.

$ bobby plan "add Google OAuth login"
2 SECTOR 2BUILD

Tests before code.

bobby writes the failing test, then makes it pass, then commits. It works in small pieces and tells you where it got confused instead of guessing. You're the reviewer, not the typist.

$ bobby build
3 SECTOR 3SHIP

Cross the line clean.

bobby opens a PR with a written account of what changed and why, linked back to the plan you approved. You read your own work. Then you merge it.

$ bobby ship

The crew you
never had to hire.

Nobody is the planner, the reviewer and the tester at one in the morning. bobby staffs the box, and each one only does its own job.

PLANNER

Reads before it writes

Breaks an epic into tickets, or a ticket into a plan with real acceptance criteria.

BUILDER

Red, green, commit

Writes the failing test first. Small commits. Stops and asks when the plan is wrong.

REVIEWER

Fresh eyes, every time

A different agent than the one that built it. Reads the diff, traces the callers.

TESTER

Drives the real thing

Opens the running app in a browser. Never grades your code by reading it.

SCRUTINEER

Only real findings

OWASP and STRIDE on what changed. Files nothing it can't write an exploit for.

SHIPPER

Opens it, doesn't merge it

Raises the PR and waits for CI. The button at the end is still yours to press.

The rules
it races under.

Every agent loads the same safety rules before it starts. These are the ones people ask about first.

It stays in its scope

No edits to files the ticket didn't name. No CI config, no environment files, no global installs.

Tests come first

Red, then green, then commit. A stage that can't show passing output doesn't advance.

Every stage is a real gate

A reviewer can throw the ticket back to building. Blocked work carries its reason in the frontmatter.

You press the last button

bobby opens the PR and waits for CI. It never force-pushes, never resets hard, never merges for you.
